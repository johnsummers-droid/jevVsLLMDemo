DEPLOY RUNBOOK: Pipeline Simulator (M3)
=======================================

Server + PostgreSQL on Render, web app on Vercel (plan1.txt section 6,
decision P1, revised 2026-10-30: Railway had suspended sign-ups after a
security incident, so Render, the planned alternative, is now primary).
The repo already holds everything code-side:
  render.yaml                              Render Blueprint: API service + PostgreSQL
  server/Dockerfile                        the API image (any Docker host)
  server/railway.json                      Railway settings, kept as a fallback (7.)
  web/vercel.json                          Vite build + rewrite of every path to index.html
  .github/workflows/ci.yml                 tests on every push
This runbook is the account-side part: about 20 minutes, done once. Every
step works in the web dashboards; CLI equivalents are noted where useful.

Deploy from main (open-terminal was merged in PR #3). Both Render and
Vercel redeploy on every push to main, so make sure CI is green on it.

0. SECRETS (keep them out of git)
---------------------------------
Generate two values and keep them in a password manager:

  TOKEN_SECRET       python -c "import secrets; print(secrets.token_urlsafe(32))"
  FACILITATOR_CODE   a passphrase you will type on the facilitator page

TOKEN_SECRET signs every team and facilitator token. Changing it later signs
everyone out (teams rejoin with their names; their graphs are kept).


1. RENDER: API AND DATABASE
---------------------------
1. render.com -> sign up with GitHub and give Render access to
   johnsummers-droid/jevVsLLMDemo.
2. Dashboard -> New -> Blueprint -> pick the repo, branch main. Render
   reads render.yaml at the repo root (Blueprint Path: leave the default)
   and shows what it will create:
     pipeline-sim-api   web service, Docker, rootDir server, 1 instance,
                        health check /api/health, deploys on every commit
     pipeline-sim-db    PostgreSQL 16; its internal connection string is
                        wired into DATABASE_URL automatically
3. It prompts once for the variables marked sync: false:
     FACILITATOR_CODE    <from step 0>
     TOKEN_SECRET        <from step 0>
   LOG_LEVEL is set by the file. ALLOWED_ORIGINS comes in step 3 below.
   The app rewrites postgresql:// to postgresql+psycopg:// itself.
4. Apply. The database starts first, then the image builds. The deploy log
   of pipeline-sim-api should show
     Running upgrade  -> 0001, sessions teams graphs
     Uvicorn running on http://0.0.0.0:<port>
5. The service page shows its URL, e.g.
   https://pipeline-sim-api.onrender.com  (= API_URL below). Check:
     curl https://API_URL/api/health          -> {"status":"ok"}

Plans: render.yaml starts on free plans. A free web service sleeps after
15 minutes without traffic (about a minute to wake, in-memory state lost);
a free database expires 30 days after creation (14 more days to upgrade
before it is deleted). For the workshop switch both to paid plans
(dashboard -> service/database -> Settings -> Instance Type, or change
`plan:` in render.yaml and sync). region, postgresMajorVersion,
databaseName and user cannot change after creation.

Editing render.yaml later: Render syncs it on push. Variables set only in
the dashboard (secrets, ALLOWED_ORIGINS) are kept by a sync.


2. VERCEL: WEB APP
------------------
1. vercel.com -> Add New -> Project -> import the same GitHub repo.
2. Configure:
     Root Directory: web           (web/vercel.json supplies build/output)
     Framework Preset: Vite
     Node.js version (Settings -> Build and Deployment): 22.x, as in CI
     "Include files outside the root directory in the Build Step": ON.
       The build imports ../shared/schema; it is on by default, but a
       build error "Could not resolve ../../../shared/..." means it is off.
3. Environment Variables (Production and Preview):
     VITE_API_BASE_URL   https://API_URL      (no trailing slash)
   It is baked in at build time: after changing it, redeploy.
4. Deploy. Note the production URL, e.g. https://jev-vs-llm-demo.vercel.app
   (= WEB_URL below), and the project's preview URL pattern.


3. CONNECT THEM (CORS)
----------------------
Render -> pipeline-sim-api -> Environment -> add:
     ALLOWED_ORIGINS       https://WEB_URL           (comma-separate several)
     ALLOWED_ORIGIN_REGEX  ^https://jev-vs-llm-demo-[a-z0-9-]+\.vercel\.app$
                           (optional: lets Vercel preview builds call the API;
                           adjust to your preview host names, or leave empty)
Save and deploy (Render redeploys with the new variables).


4. POST-DEPLOY CHECKS
---------------------
From a terminal:
  curl -s https://API_URL/api/health
      {"status":"ok"}
  curl -s -o /dev/null -D - -X OPTIONS https://API_URL/api/sessions \
       -H "Origin: https://WEB_URL" -H "Access-Control-Request-Method: POST"
      HTTP 200 and access-control-allow-origin: https://WEB_URL

In browsers (the M3 exit criteria):
  [ ] https://WEB_URL/facilitator: enter FACILITATOR_CODE -> a session code.
  [ ] Browser A (normal window) and browser B (private window, or another
      browser): open https://WEB_URL/join?code=<code>, join as "Red" and
      "Blue". Both see the starter graph.
  [ ] Each adds a different node; the header says "Saved".
  [ ] Refresh both: each still has its own node, not the other team's.
  [ ] Open https://WEB_URL/team directly in a new tab of A: it loads (no
      404), so the rewrite works.
  [ ] Facilitator page lists Red and Blue. Press "Pencils down": within
      10 seconds both teams show the lock banner, a disabled palette and
      "Locked", without touching anything.
  [ ] "Unlock graphs": within 10 seconds both are back to "Saved" and can
      edit again.

If all boxes are ticked, M3 is done on the deployed URLs.

Going live on real AI (T38; the modes stay mock in render.yaml until T39):
  [ ] Render's dashboard holds working TYPESAFE_API_KEY and GEMINI_API_KEY. Both
      modes need TypeSafe: Jev judges the real replies.
  [ ] Locally, with the keys in server/.env: `scripts/live_check.py jev` and
      `scripts/live_check.py llm` both answer. A bad key shows on every ticket
      (the server's startup check only sees that a key is set).
  [ ] Look up the Gemini key's rate limit in AI Studio. On 2026-11-01: 1000 RPM,
      2M TPM (gemini-4-argon) and 4000 RPM, 4M TPM (flash-lite).
      LIVE_LLM_CONCURRENCY=32 fits those; lower it if the tier drops.
  [ ] Set JEV_MODE and LLM_MODE to live in render.yaml, in a PR. A Blueprint
      sync applies these values, so a dashboard-only change wouldn't last.
  [ ] Prewarm production: `scripts/prewarm.py` where DATABASE_URL points at it
      (with the live modes and keys set). A rerun replays for free.
  [ ] /api/health shows "jevMode":"live", "llmMode":"live". A practice run says
      "Preparing...", then plays with real latencies.
  [ ] LIVE_SPEND_CAP_USD (default 10 per UTC day) suits the day. At the cap, new
      requests answer from the mocks and the team and facilitator see a warning;
      their numbers can't be compared with a fully live run.

Live runs (the M4 exit criteria; spec section 11 end to end):
  [ ] Two teams (two browsers) each press "Run traffic": dots move along
      the edges, node badges count up, the metrics bar fills in and is
      coloured, the score shows at the end.
  [ ] Facilitator: "Pencils down" -> both teams show the banner at once
      (not after a 10 s poll); unlock likewise.
  [ ] /screen open in the facilitator's browser (second tab). Facilitator:
      "Start official run" -> confirm: both teams run (their pages say
      "Official run"), the team list says "Official · running", and the
      leaderboard on /facilitator and /screen fills in as teams finish.
  [ ] Reconnect: switch a team's laptop offline (or close the lid) mid-run
      for ~15 s, then back: within ~40 s the page is live again and the
      run's numbers catch up.
  [ ] The facilitator page's green dot (next to "Official run") stays
      green; amber means it is reconnecting.

WebSocket notes: the browser talks to wss://API_URL/api/ws directly (not
through Vercel). Render's proxy swallows WebSocket close frames, so the
server sends a `closing` event before every close and answers pings with
`pong`; the client reconnects after 40 s of silence. Check from a terminal
with a bad token: it must answer {"type":"closing","code":4401,...}.


5. TROUBLESHOOTING
------------------
  Browser console: "blocked by CORS policy"
      ALLOWED_ORIGINS does not contain the exact origin (scheme, host, no
      trailing slash, no path). Fix it in Render and wait for the redeploy.
  "Could not reach the server" on every page
      VITE_API_BASE_URL is missing or wrong in Vercel; fix it and redeploy
      (it is read at build time).
  Facilitator page: "The server has no FACILITATOR_CODE or TOKEN_SECRET set"
      Set both in the Render service's Environment.
  A refresh of /team or /join gives Vercel's 404
      Root Directory is not web/, so web/vercel.json is not used.
  Render deploy fails at "alembic upgrade head" / connection refused
      DATABASE_URL is missing (the service was not created from the
      Blueprint) or the database is still starting; redeploy.
  The first request after a quiet spell takes about a minute
      The free web service was asleep; use a paid instance for workshops.
  "Run traffic" stays greyed out with "Connecting to live updates…"
      The live socket cannot connect: check that wss://API_URL/api/ws is
      reachable (no proxy on the venue network blocking WebSockets) and
      that VITE_API_BASE_URL is https://API_URL (the socket URL is derived
      from it).
  Live views freeze after a deploy
      Expected for up to ~40 s: the client notices the silent socket and
      reconnects, then catches up. Don't deploy during a session.
  Blueprint creation: "free database limit reached"
      Only one free PostgreSQL per workspace; delete the old one or pick a
      paid plan.

7. FALLBACK: RAILWAY
--------------------
Railway works with the same image once it accepts sign-ups again:
New Project -> Deploy from GitHub repo; service Settings: Root Directory
server, Branch main, Railway config file /server/railway.json (sets the
Dockerfile builder, 1 replica, health check); + Create -> Database ->
PostgreSQL; variables DATABASE_URL = ${{Postgres.DATABASE_URL}} (typed
exactly like this), FACILITATOR_CODE, TOKEN_SECRET, LOG_LEVEL info,
ALLOWED_ORIGINS; Settings -> Networking -> Generate Domain. If the build
uses Nixpacks/Railpack instead of the Dockerfile, the config file path is
not set.
